**现状问题**：微信小程序所有网络请求必须走 HTTPS 且域名需在 MP 后台白名单配置。当前 `instance.ts` 的 `baseURL` 为 `https://petstore3.swagger.io/api/v3`（Swagger 示例地址），生产环境 `.env.production` 为占位 `https://api.yourapp.com`。

- request 合法域名：每个域名必须 HTTPS、已 ICP 备案、端口 443
- socket 合法域名：wss 协议（如果用 IM WebSocket）
- uploadFile / downloadFile 合法域名
- 最多 200 个域名

**需要做的事**：
- [ ] 购买域名并完成 ICP 备案（约 7-20 个工作日）
- [ ] 部署后端服务到云服务器，配置 HTTPS 证书

- [ ] `manifest.config.ts` 中 `mp-weixin.setting.urlCheck` 当前为 `false`（跳过域名校验），上线前必须改为 `true` 或删除

## 四、分账体系（核心商业闭环，需领导重点关注）

> 以下内容基于对设计文档 V3.0 和全部代码的逐行审阅。微信支付文档已确认「分账」是独立的支付产品线，需在商户平台单独申请开通。

### 4.1 平台涉及的 6 条分账链路

| # | 场景 | 资金流向 | 当前代码状态 | 佣金比例 |
|---|------|----------|-------------|---------|
| 1 | **CAAC 考证报名** | 学员支付 → 平台监管账户 → 平台抽佣 15%-25% → 机构到账 75%-85% | `learn-enroll` 页面有"报名即分账"文案，但仅 Toast 模拟，无真实支付和分账 | 平台 20%（默认），机构 80% |
| 2 | **订单撮合（定金+尾款）** | 需求方支付 → 平台监管账户托管 → 验收后平台抽佣 10%-20% → 飞手/企业到账 80%-90% | `order-detail` 页面有"定金已托管"文案，`apiGrabOrder` 仅 Mock 返回成功 | 阶梯递减：0-50单 20%，51-200单 15%，201-500单 12%，500+ 10% |
| 3 | **电商交易（商品）** | 买家支付 → 平台监管账户 → 平台抽佣 3%-8% → 卖家到账 92%-97% | `mall` 页面仅有商品列表，无下单和支付流程 | 全新商品 5%-8%，二手 3%-5% |
| 4 | **维修服务** | 用户支付 → 平台托管 → 验收后扣佣 → 维修商到账 | `repair-apply` 有维修商报价对比，`repair-accept` Mock 返回"托管款已扣佣结算" | 初级 20%，中级 15%，品牌授权 5% |
| 5 | **技能培训补贴分成** | 人社补贴发放 → 平台抽取服务费 5%-10% → 培训机构到账 | `subsidy` 页面有补贴金额展示，无真实补贴资金流转 | 平台 5%-10% |
| 6 | **飞手保证金管理** | 飞手缴纳 500-2000 元 → 平台资金池沉淀 → 违约时扣除 | `mine` 页面展示"保证金已缴纳 ¥1000"（Mock 硬编码），无真实缴纳和扣除流程 | 非佣金，是保证金沉淀 |

### 4.2 微信支付分账产品的申请与对接

**微信支付文档确认**：分账是微信支付的独立产品线，需要在商户平台单独开通。

**申请条件**：
- 需要先有微信支付商户号（JSAPI 支付）
- 分账功能需在商户平台「产品中心」申请开通
- 分账接收方需添加为「特约商户」或「个人微信账户」

**需要做的事**：
- [ ] 在微信支付商户平台开通「分账」产品
- [ ] 添加分账接收方：培训机构（企业对公账户）、飞手（个人微信/银行卡）、商家（企业对公账户）
- [ ] 后端实现分账 API 调用（`profitsharing/orders`，微信支付 V3 接口）
- [ ] 分账比例上限：微信支付限制单笔分账比例最高 30%，超过需申请提额
- [ ] 分账有冷却期：支付成功后需等待一定时间（通常 1 天后）才能发起分账
- [ ] 分账资金到账：T+1 结算到接收方微信支付账户，再提现到银行卡

**⚠️ 关键限制**：
- 微信支付分账**单笔最高 30%**，平台 CAAC 抽佣 15%-25% 在限制内，但电商和维修的佣金也在此范围内
- 如果佣金比例超过 30%（比如某些场景），需要走「分账比例提额申请」或改用「商户转账」产品
- 分账**不能实时到账**，有 T+1 结算周期，UI 上的"报名即分账·机构实时到账"文案需调整或做技术补偿

### 4.3 资金托管与分账机制（采用微信支付官方分账，无需银行监管专户）

**架构决策**：平台已全面决策**不接入商业银行监管专户/银企直联**，直接采用**微信支付官方分账产品（Profit Sharing）**自带的 30 天资金冻结与自动分润能力。

**核心运作逻辑**：
1. **资金冻结托管**：学员报名/需求方付定金时，调用 JSAPI 支付并标记 `profit_sharing: Y`。支付成功后，款项自动冻结在微信支付商户号待分账资金池中（最长 30 天）。
2. **履约验收分账**：课程确认开课或作业验收合格后，平台后端调用微信支付分账接口（`profitsharing/orders`），微信按约定比例将款项分别划入接收方账户（机构对公商户号、飞手微信零钱）及平台商户号。
3. **退款保障**：冻结期内发生退款/纠纷，直接调用微信退款 API 从冻结资金出款原路退回，不影响平台商户可用余额。
4. **彻底规避二清**：资金全程流转于微信持牌支付清算通道内，不经由平台自有银行账户，合规风险降为最低。

**需要做的事**：
- [ ] 申请微信支付商户号并开通 JSAPI 支付与「分账」产品（直连商户模式）
- [ ] 添加分账接收方：培训机构（企业对公商户号）、维修商（企业对公商户号）、飞手（个人微信号/OpenID）
- [ ] 后端实现分账请求、分账查询、解冻剩余未分资金接口
- [ ] 后端记录每笔订单冻结、分账凭证（微信分账单号、商户分账单号、接收方、金额、分账时间）

| **资金池/备付金** | 飞手保证金与退款准备金管理 | 平台商户号保留充足运营备付资金，保障随时退还 |
| **分账到账周期** | 微信支付分账为 T+1 结算后分账 | 小程序 UI 统一规范文案为"T+1 分账到账"，避免用户误解 |
| **发票与税务** | 平台抽佣收入需开具发票；飞手收入涉税；企业客户要专票 | 平台按佣金开票，企业订单提供增值税专票抵扣 |
| **风控限额** | 大额交易、异常分账风控 | 接入风控管理中枢，设置单笔/单日上限与异常拦截规则 |
